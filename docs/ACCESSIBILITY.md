# Accessibility controls and qualification

## Requirements and scope

The owner supplied a Greek requirements extract, printed pages 151-152 (section E), and UserWay screenshots. They selected an in-house implementation with a floating launcher rather than a header button. The extract calls for WCAG 2.1 AA and EN 301 549 chapter 9 for websites, chapter 10 for non-web documents, and compatibility with assistive technologies. Its recommendation for authoring tools references ATAG 2.0. No external overlay service, subscription or tracking is used.

The public consultancy is not represented as a service specifically for disabled people, so the extract's special-case AAA passage is not automatically assumed. This is a technical implementation target, not a legal applicability determination or certification. Normative references: https://www.w3.org/TR/WCAG21/ and https://www.etsi.org/deliver/etsi_en/301500_301599/301549/03.02.01_60/en_301549v030201p.pdf. W3C guidance for reflow: https://www.w3.org/WAI/WCAG22/Understanding/reflow.html.

## Experience

Settings owns launcher availability and desktop right-middle/right-bottom placement. Small screens use right-bottom. A named native modal drawer provides localized controls and a reset. Escape closes and returns focus; Tab and Shift+Tab remain within the panel. It has a scrollable body and visible focus. No reserved browser shortcut is captured. Existing automatic newsletter scheduling waits while a dialog is open.

Preferences are scoped by app and version. They contain no personal data, are applied only when the feature is enabled and can be reset. An unavailable storage API falls back to the current page with feedback. Browser zoom, operating-system accessibility settings and screen readers remain authoritative. The panel uses finite values and external scripts/styles under the existing public CSP; it never accepts arbitrary CSS or adds third-party requests.

Base text grows to 200% with wrapping. The percentage describes the root/base text scale; responsive headings retain their fluid clamp behavior and need not double pixel-for-pixel. Browser zoom remains available for proportional enlargement. Text/line spacing and readable sans-serif headings are preferences, not medical interventions. Contrast modes remap semantic tokens at section boundaries, including form feedback and button aliases. Decorative backgrounds/empty-alt photographs can be hidden, while meaningful images and names remain available. Motion controls stop existing scroll/menu animations and respect system reduced motion. Pointer enhancement is a local SVG cursor with a native fallback; platform cursor rendering varies.

## Verification evidence

Initial baseline: axe WCAG 2.1 A/AA scan across 32 public content routes at 1440px and 375px, 64 checks, no automatic violations. This is not proof of conformance: axe also reported incomplete checks requiring human review (colour contrast and ARIA cases). Panel tests cover EN/EL, native keyboard operation, persistence/navigation/reset, blocked storage and 320px reflow at 200% text/maximum spacing. Native CMS position save/reload has been verified through the installed editor. Detailed final results are recorded after acceptance below. Raw local logs/screenshots remain under ignored `.generated/accessibility-*`.

## Manual qualification still required

- NVDA/Firefox or Chrome and VoiceOver/Safari reading order, labels, native form error/status announcements, panel controls and full enquiry/newsletter journeys.
- Real browser zoom/reflow, forced colours, user styles, keyboard focus visibility/obscuration and all theme/background image combinations on actual devices. Text-scaling and narrow-viewport tests are useful evidence but do not substitute for real browser zoom checks.
- Verify alt text conveys the intended meaning when editors replace media; review new rich text, headings, links and publication changes.
- Audit any downloadable PDF/Office document before publishing it against applicable EN 301 549 chapter 10 requirements. The user's source PDF is in Downloads and is not published by this site.
- Assess TinaCMS authoring workflows separately if the owner requires a CMS/ATAG report. The public widget intentionally does not alter the CMS.
- Review the complete applicable success criteria and record method, evidence, exceptions and remediation before making any formal conformance statement.

No blanket accessibility certification or compliance badge is generated by these controls.

## Final local acceptance (2026-10-22)

- 21 tests passed with the live browser and static-CSP suites enabled, including keyboard cycling, Escape/focus restoration, EN/EL, preference navigation/reset, storage denial, computed control styles, cross-tab updates and Greek FAQ reflow.
- 90 layout checks across EN/EL, 1440/375/320px and five representative page types with default, 200% base text, and combined maximum text/spacing/line-height preferences: no horizontal overflow. A real Greek FAQ overflow was fixed by allowing the question to shrink/wrap beside its toggle.
- 18 panel axe checks across three widths, both languages and three contrast modes: no automatic violations. Another 20 representative public-page checks in both high-contrast modes: no automatic violations. These are automated observations, not a complete conformance assessment.
- Actual computed styles verified text scale, spacing, line height, link underline, simple headings, decorative image hiding, saturation, alignment, local pointer and larger drawer. A meaningful-alt fixture remained visible. Cross-tab changes/reset propagated correctly.
- Native TinaCMS desktop position changed right-middle → right-bottom, saved/reloaded and restored through the installed editor. No page errors.
- Strict-CSP regression: the existing newsletter schema's caught Zod JIT probe emitted script-src:eval under the production policy. Browser contracts now select Zod's interpreter before constructing schemas; server/Worker configuration and validation rules are unchanged. The static-browser regression failed before this change and passed after rebuilding.
- Scroll regression: an unfocused document body must not trigger launcher overlap suppression. The browser test reproduced the hidden launcher before the fix and passed after restricting suppression to actual focused elements.
- One independent final code review found no Critical/Important issues. Its minor fluid-heading observation was addressed by qualifying the control as **Base text size** in both languages and documenting the scaling boundary above. Dark-mode validation error contrast was also checked in the browser.

Build, packaged release and strict-CSP serving evidence follows in the verification record. Manual qualification gates above remain open.

## Panel interaction polish

The panel uses the site's blue palette and control radius with a compact header, icon wells and explicit current-value chips. Each tile includes a localized instruction: cycle controls say “Tap to change”; boolean controls switch between “Tap to enable” and “Tap to disable” as their state changes. Selected chips include a checkmark so selection does not depend on color alone. Existing accessible labels, pressed states and keyboard behavior remain authoritative.

Opening uses a short 220ms side entrance. Hover lift is limited to devices with hover capability. Both the device reduced-motion preference and the panel's motion setting suppress these movements; device reduced motion also removes tile transitions. Twelve EN/EL panel checks across desktop/320px and default/dark/light modes found no automatic axe violations or panel overflow. Explicit instructions, state changes and reduced-motion suppression were checked in the browser.
